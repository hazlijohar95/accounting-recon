## Keyboard Shortcuts

Master these shortcuts for 10x faster review:

| Key | Action | Description |
|-----|--------|-------------|
| `A` | Approve | Approve the selected match |
| `R` | Reject | Reject the selected match |
| `↑` | Previous | Move to previous match |
| `↓` | Next | Move to next match |
| `Enter` | Details | Open match details panel |
| `Esc` | Close | Close details/modal |
| `Space` | Select | Toggle selection for bulk actions |
| `?` | Help | Show keyboard shortcuts |

<Tip>
  Start with the Suggested tab and work through matches using `↓` to move and `A` to approve. You can process 50+ matches per minute this way.
</Tip>

## Reviewing a Match

Each match row shows:

**Left side (Bank Transaction):**
- Amount and date
- Transaction description
- Bank reference

**Right side (Invoice/Receipt):**
- Invoice number and date
- Vendor/customer name
- Invoice amount

**Match Info:**
- Confidence percentage
- Which layer matched it
- Matching factors (hover for details)

### Match Details Panel

Press `Enter` to see full details:

- Complete transaction description
- Full invoice details
- Why it matched (matching criteria met)
- Historical matches with same vendor
- Amount breakdown (if split)

## Approval Workflow

<Steps>
  <Step title="Filter to Suggested">
    Click the **Suggested** tab to see matches needing review
  </Step>

  <Step title="Review First Match">
    Check the bank transaction matches the invoice:
    - Amounts align
    - Dates make sense
    - Descriptions relate
  </Step>

  <Step title="Approve or Reject">
    - Press `A` to approve (match is confirmed)
    - Press `R` to reject (goes back to unmatched)
  </Step>

  <Step title="Next Match">
    Press `↓` to move to the next suggested match
  </Step>

  <Step title="Repeat">
    Continue until all suggested matches are reviewed
  </Step>
</Steps>

## Handling Suspense Items

Suspense items require more attention:

### Finding a Manual Match

1. Select an unmatched bank transaction
2. Click **Find Match** or press `M`
3. Search available invoices by:
   - Amount range
   - Date range
   - Vendor name
   - Description keywords
4. Select the matching invoice
5. Confirm the manual match

### Marking as No Match

Some transactions won't have a match (bank fees, interest, etc.):

1. Select the transaction
2. Click **No Match** or press `N`
3. Choose a reason:
   - Bank charge
   - Interest
   - Timing (will match next period)
   - Write-off
4. Add optional notes
5. Confirm

### Creating an Invoice

If an invoice is missing:

1. Select the unmatched bank transaction
2. Click **Create Invoice**
3. Pre-filled form opens with transaction details
4. Complete any missing fields
5. Save—automatically matches to the transaction

## Bulk Actions

For efficiency with many similar items:

1. Use `Space` to select multiple matches
2. Or use **Select All** in current filter
3. Choose bulk action:
   - **Approve All** — Approve all selected
   - **Reject All** — Reject all selected
   - **Export Selected** — Export for review

<Warning>
  Bulk approve carefully. Always filter first to ensure you're only approving appropriate matches.
</Warning>

## Best Practices

<AccordionGroup>
  <Accordion title="Review in order of confidence">
    Start with highest confidence suggested matches. These are quickest to verify and approve.
  </Accordion>

  <Accordion title="Use keyboard exclusively">
    Mouse clicking is 5x slower than keyboard shortcuts. Learn the shortcuts for major speed gains.
  </Accordion>

  <Accordion title="Review suspicious low-confidence matches">
    If a match seems wrong, reject it. It's easier to manually match later than fix an incorrect auto-match.
  </Accordion>

  <Accordion title="Process suspense items last">
    Focus on suggested matches first. Suspense items take more time and might resolve as you process other matches.
  </Accordion>

  <Accordion title="Take notes on patterns">
    If you notice recurring mismatches (e.g., vendor name variations), note them. You can add aliases in Settings to improve future matching.
  </Accordion>
</AccordionGroup>
